# 推理成本的构成

一次推理调用的成本由输入 token 和输出 token 分别计价，输出单价通常是输入的 3 到 5 倍。以 DeepSeek-V3.2 为例，输入每百万 token 0.22 美元，输出每百万 token 0.33 美元，比值约 1.5 倍；而某些闭源模型的输出输入比可以达到 4 倍。

成本结构里最容易被低估的是重试。生产环境的重试率通常在 2% 到 7% 之间，重试会同时放大输入和输出成本。我们统计过一个未做幂等控制的检索服务，重试率 11%，实际成本比账单预估高出 26%。

另一个隐藏项是上下文膨胀。多轮对话里如果每轮都重发全部历史，第 10 轮的单次输入可能是第 1 轮的 8 倍。一个 20 轮对话的总输入 token 是首轮的 210 倍左右，因为它是等差累加而不是线性增长。

降低成本的三个有效手段，按投入产出排序：

第一是前缀缓存。当系统提示词和工具定义固定时，前缀缓存可以把这部分输入的计费降到原价的 10%，在长系统提示场景下能省 40% 到 60% 的总输入成本。

第二是模型分级。把简单请求路由到小模型，实测可以把 60% 的流量分流出去，总成本下降 55%，而端到端质量在人工抽检中只下降了 1.2 个百分点。

第三是输出约束。给 max_tokens 设合理上限，并在提示词里要求简短回答，可以把输出长度压到原来的 60%，直接对应 40% 的输出成本节省。

需要强调的是，这三项都改变不了单价，只改变用量。真正的单价谈判发生在采购阶段。
